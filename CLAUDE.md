# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Repository layout

This repo has two independent projects with no shared build/tooling:

- `backend_app/` — Node.js/TypeScript/Express bridge that parses bank statement PDFs and imports transactions into [Actual Budget](https://actualbudget.org) via `@actual-app/api`.
- `mobile_app/` — Flutter app (Riverpod + go_router) that is the client for that backend: upload a statement, review parsed transactions, confirm/ the import.

Everything below a project's own directory should be treated as that project's scope; there's no monorepo tooling tying them together. The one shared thing is `fixtures/`: synthetic statement text the app's Dart parsers (`mobile_app/packages/statement_parser`) are tested against, and golden `importedId`s that both the app and the backend check, so a statement imports with the same ids however it was read. Never put real statement text in it; real statements go in the gitignored `backend_app/Docs/tests/`.

## backend_app

### Commands

Run from `backend_app/`:

```bash
npm install
cp .env.example .env        # fill in ACTUAL_* values; see comments in the file
npm run dev                 # ts-node-dev, auto-restarts on change
npm run build                # tsc -> dist/
npm start                    # node dist/server.js (run build first)
npm test                     # builds first (pretest hook), then node --test "dist/**/*.test.js"
```

Tests execute from `dist/`, not `src/` — the `pretest` hook rebuilds so a stale `dist/` can't report a false pass. There is no single-test-file npm script; run one compiled test directly, e.g. `npm run build && node --test dist/__tests__/categorydb.test.js`.

`GET /health` returns `{ "status": "ok" }` once the server is running — no auth required on that one route.

### Architecture

**Parsing pipeline** (`src/index.ts` is the entry point, `processStatement()`):
- Statements are read **on the phone** (`mobile_app/packages/statement_parser`). The backend's regex parsers and `PARSER_MODE` were removed (docs/plans/dart-parser.md, Phase 6); a leftover `PARSER_MODE` in `.env` only logs a warning.
- `processStatement()` is AI-only: the PDF's raw bytes go straight to the AI provider (more layout fidelity). Without a configured provider it throws `AiNotConfiguredError` (`AI_NOT_CONFIGURED`, 409); the backend still starts. `GET /config` reports `parserMode` `"ai"` or `"off"`.
- The AI parser (`src/parsers/aiparser.ts`) implements the `BankParser` interface (`src/types.ts`).
- AI vendors are behind a Strategy interface, `AiProvider` (`src/parsers/ai-providers/types.ts`); `src/parsers/ai-providers/index.ts` is the factory picking anthropic/gemini via `AI_PROVIDER`. Code outside `ai-providers/` never touches a vendor SDK directly. **Adding a new vendor**: one new file implementing `AiProvider`, plus one line in that folder's `index.ts` factory map.
- Password-protected PDFs can't go to a provider as bytes (no way to decrypt them), so that statement is decrypted and extracted locally (`extractText`, pdf-parse) and the text goes to the text-based AI parser. pdf.js password error codes map to `PdfPasswordRequiredError` (code 1) / `PdfPasswordIncorrectError` (code 2) in `src/errors.ts`.

**Import flow**, in `src/server.ts`:
- `POST /parse` (extracts + returns transactions with a `suggestedCategoryId`/dedupe `importedId`, does *not* touch Actual) → client reviews/edits → `POST /import/confirm` (JSON, actually imports). Editing a transaction's date/amount/payee client-side and re-submitting must still pass back the original `importedId` unchanged, since that id is derived from those three fields and re-deriving it after an edit breaks dedupe on re-import of the same statement. Ids are stamped by `assignImportedIds` (`src/actual.ts`) over the **whole statement at once**, never per transaction: date+amount+payee is not unique within a real statement (banks truncate the payee column, and repeat transfers on one day are ordinary), so repeats of one basis are numbered as they are found. Occurrence 0 keeps the pre-numbering id, and `actual.test.ts` pins those ids as literals — changing the basis or the hash silently duplicates every past import.
- The legacy one-shot `POST /import` was removed with the regex parsers.
- Undo: `POST /import/confirm` returns the `addedIds` it created; `POST /import/undo` takes them back and **soft-deletes**: nothing is deleted in Actual, each transaction gets amount 0 and a note starting `[Removed via PDF importer`, and the original amount/notes go to the backend's removal log (`src/removal-log.ts`, `removed-transactions.db` next to the category DB). Only transactions still carrying a `pdfimport-` `imported_id` are touched, and already-removed ones are skipped, so the log always holds the real original. Re-importing the same statement afterwards is a no-op (the zeroed transaction still matches by `imported_id`).

**Backups** (`src/backup.ts`, `src/backup-schedule.ts`; `docs/plans/backups.md`): the budget is backed up with `port.exportBudget()` inside one `withBudget` turn (the same zip as Actual's Export; restored by hand with Actual's Import file → Actual, which makes a new budget). App data (`app_categories`, live mappings, the removal log) is gzipped JSON with a `manifest.schemaVersion`; restoring it writes every row as a new edit at "now" and tombstones mappings the backup lacks, so the normal `/categories/sync` carries it to phones (no file swapping). Files go to `BACKUP_DIR/<app-data|budget sync id>/<stamp>` via `.tmp` + rename and are only ever reached through `findBackup`'s listing (never a path built from input). The schedule is a pure `nextDue` checked every 15 minutes (no cron); failures retry after an hour and never prune. Everything past listing needs `IMPORT_TOKEN` (`AUTH_REQUIRED` otherwise).

**Dashboard** (`src/dashboard.ts`): `GET /dashboard?budgetSyncId=&months=6` returns read-only metrics (balances, net worth, monthly income/spending, top categories and payees, uncategorized count, recent transactions). `getDashboard` does one `withBudget` turn; `buildDashboard` is pure and unit-tested. Flows count on-budget accounts only and exclude transfers and opening balances; split transactions are read by their children for flows and by the parent for balances. The module deliberately doesn't import `categorydb` so its tests need no SQLite.

**Everyday screens**, one call per screen, each a budget turn plus a pure `build*` function: `POST /transactions` (`src/transactions.ts`, quick add: created with `addTransactions` — `importTransactions` would fuzzy-match a second identical purchase within ±7 days and swallow it — and idempotent through `imported_id: "app-<clientId>"`; also teaches the category memory), `GET /quick-add/options`, `GET /accounts/:id/transactions` (`src/account-page.ts`, newest first, cursor = last row's id) and `GET /budget-month` (`src/budget-month.ts`, shaped from Actual's `getBudgetMonth`, read-only).

**Budget session** (`src/budget-session.ts`, term defined in `CONTEXT.md`) owns the one global connection `@actual-app/api` allows: one downloaded budget at a time. All Actual work runs as `session.withBudget(budget, fn)` (or `withServer(fn)` when no budget is needed): turns are strictly serialized and the *whole callback* runs inside the turn, so another request can't swap the budget mid-operation. A budget that's already loaded isn't re-downloaded; a failed download marks nothing as loaded. Never call `withBudget`/`withServer` from inside a callback (deadlock). The Actual connection is **optional** (`src/actual-connection.ts`): from `ACTUAL_SERVER_URL` in `.env` (then *locked*), else from what the app saved via `PUT /actual/connection` (`actual-connection.json`, mode 0600, next to the category DB), else none — every turn then throws `ACTUAL_NOT_CONFIGURED` (409) without touching the SDK. `session.reconfigure(config | null)` swaps servers as a queued turn, no restart. Reads within `SYNC_INTERVAL_MS` of the last sync reuse the local copy; pass `{ write: true }` to `withBudget` for anything that changes the budget (syncs before and pushes after). `PUT`/`DELETE /actual/connection` need `IMPORT_TOKEN` set (`AUTH_REQUIRED`); `PUT` probes the server first (`/info` version ≥ the library's, then a login) and only saves what works. `src/actual-adapter.ts` is the only file that drives the SDK's lifecycle (init/download/shutdown), and callbacks only see the narrow `ActualPort` type. Tests use a fake `ActualAdapter` (`src/__tests__/budget-session.test.ts`).

**`src/actual.ts`** holds the domain operations (`importToActual`, `learnCategoriesFromActual`, `listAccounts`, `listCategoryGroups`, `listBudgets`, `assignImportedIds`); each takes the `BudgetSession` and a `BudgetRef` (`{ syncId, budgetPassword? }`) instead of touching the SDK directly.

**`src/categorydb.ts`** is a local SQLite-backed payee→category memory (not Actual's own category data), scoped per `budgetSyncId` with an "unscoped" fallback for mappings created before scoping existed. It's a complement to Actual's fuzzy rules engine, not a replacement — matching here is exact on cleaned/normalized payee text. Populated either directly (`POST /categories`) or backfilled from already-categorized Actual transactions (`POST /categories/learn-from-actual`, implemented as `learnCategoriesFromActual` in `src/actual.ts`).

**Errors** (`src/errors.ts`): route handlers throw a typed `ImporterError` subclass (never a plain `Error`, for expected failure modes); `server.ts`'s `sendImporterError()` maps it straight to a JSON response with a stable machine-readable `code` field. Clients should branch on `code`, never on the English `error` message. `resolveBudgetRef` in `server.ts` is where an unset budget becomes `NO_BUDGET_SELECTED` (400) rather than an empty sync id reaching `downloadBudget()`; routes that only need the category-memory scope key use `resolveBudgetScope`, where empty is legitimate.

**Auth**: a single shared-secret header, `X-Import-Token`, checked with `crypto.timingSafeEqual` (`src/server.ts`). Every route requires it except `GET /health`. Leaving `IMPORT_TOKEN` unset in `.env` disables auth entirely (loudly logged at startup) — acceptable for local testing only.

**Logging** (`src/logger.ts`, pino): `logger.child({ area })` per module — never `console.*`. Debug lines need `LOG_DEBUG=true`; info/warn/error always go to stdout and rotated files in `LOG_DIR`. `request-log.ts` gives every request an `X-Request-Id` (the app's, or a new one), echoes it, returns it in error JSON, and logs one line per request with the route *pattern* (so a payee in `/categories/:payee` never reaches an info line). What may be logged is enforced by field name in `redactFields`: secrets replaced, amounts/balances/`rawLine` always dropped, payees only at debug, ids always fine — keep field names meaningful (`payee`, `amountCents`) so the rules apply. `sendImporterError` logs typed errors at warn and anything else at error with its stack. `GET /logs` returns recent lines for the app's "Share logs" and is refused (`AUTH_REQUIRED`) when `IMPORT_TOKEN` is unset.

**Privacy invariant**: uploaded PDFs are handled via `multer.memoryStorage()` only — never written to disk. Keep this in mind before changing upload handling.

## mobile_app

Flutter app, no CLI-buildable commands verified in this environment beyond the standard `flutter pub get` / `flutter run` / `flutter analyze` / `flutter test`. `analysis_options.yaml` includes the standard `flutter_lints` set with no project-specific overrides.

### Architecture

- State management: Riverpod. All providers are centralized in `lib/data/providers.dart` — `appConfigProvider` (backend URL + active budget, kept atomic via `copyWith` so a budget switch never leaves syncId/name out of sync) drives `apiClientProvider`, which rebuilds a fresh `Dio` instance (`lib/data/api/api_client.dart`) whenever the backend URL changes, rather than mutating `baseUrl` on a shared instance in place.
- Routing: go_router (`lib/core/router.dart`), a single `GoRouter` built once via a `Provider`. Main tabs (Home `/dashboard`, Budget `/budget`, Import, Settings) are a `StatefulShellRoute` wrapped by `lib/core/app_shell.dart`, which also shows the quick-add button on Home and Budget; `/dashboard/accounts/:id` is the account screen. `/welcome`, `/setup`, `/review`, `/add` (quick add), `/settings/categories` (category memory), `/settings/diagnostics` and the debug-only `/dev` are full-screen. The app starts on Import when no budget is chosen. A `redirect` callback (re-evaluated on every navigation) sends everything except the onboarding routes to `/welcome` until `AppConfig.onboarded` is true. Installs from before onboarding existed count as onboarded if they already have a backend URL and budget.
- Onboarding: `features/welcome` (animated intro) → `features/setup` (2 steps, nothing required: "How it works", then "Bring your budget along" — `features/setup/widgets/actual_step.dart`, which connects backend → Actual server → budget in place, or "Not now"). Setup and Settings share `features/settings/connection_controller.dart` (backend checks, the Actual server via `/actual/connection`, budgets) and `features/settings/widgets/actual_server_card.dart`.
- Optional connections: the backend and Actual are both optional. `linkStateProvider` (`noBackend` / `noActual` / `noBudget` / `ready`) drives `RequiresActual` and `ConnectActualState` (`shared/widgets/connect_actual_state.dart`), the one "connect first" state every Actual screen shows instead of an error; `isActualNotConnected(error)` maps `ACTUAL_NOT_CONFIGURED`/`NO_BUDGET_SELECTED` responses to it.
- Import inbox: `features/import/inbox_controller.dart` queues PDFs in memory only (never on disk) and parses them one at a time. By default it reads them **on the phone** (`data/pdf/`: `pdfrx` text extraction, then `statement_parser`) and only fetches the backend's category mappings for suggestions, never sending the PDF. A statement no built-in parser recognises becomes `InboxStatus.unrecognized` and goes to the backend's `/parse` (AI) only when the user taps "Send to backend" and confirms. Settings → "Read statements on this phone" (`parseOnDeviceProvider`) off brings back backend parsing for everything. Review opens without an Actual account too and then offers CSV export instead of import (`features/review/csv_export.dart`). Categories: the app has its own (drift, `data/local/db/`: predefined English presets seeded by stable key, user categories `local:<uuid>`, a payee → category memory keyed like the backend's) used while Actual isn't connected; local ids must never reach Actual, so they're translated through `category_links` ("Match your categories", `/match-categories`) or dropped (`features/categories/category_matching.dart`). `POST /categories/sync` (backend `syncCategories`, app `CategorySync`) keeps both sides' memory and the app's categories in step, newest wins per row; forgetting a mapping is a tombstone on both sides, never a DELETE. Review pops back with the `ImportResult` so the inbox can mark the item and record it in `ImportHistoryStore` (metadata only, `shared_preferences`). Share-sheet intake lives in `AppShell` so it works from any tab.
- Logging: `lib/core/log/` — `const _log = AppLog('area')`, never `print`. `Logs.init` in `main()` wires the sinks: an in-memory buffer (the Diagnostics viewer; the only store on web), daily JSON files on the device (always on, 7 days / 5 MB), and the console in debug builds. Debug lines need the flag: `--dart-define=LOG_DEBUG=true` sets the default, Settings → Diagnostics ("Verbose logging") overrides it at runtime. `redaction.dart` mirrors the backend's field-name rules. `HttpLogInterceptor` adds `X-Request-Id` to every request and logs method/path/status/duration; global error hooks (`error_hooks.dart`) log uncaught Flutter/async/provider errors with stacks. Settings → Diagnostics shares the files plus the backend's `GET /logs`.
- Dev page: `/dev` exists only in debug builds (long-press the title on Welcome or Settings). Its preset comes from `flutter run --dart-define-from-file=dev.json` (copy `dev.example.json`; `dev.json` is gitignored).
- The drift database file is **encrypted** (SQLite3MultipleCiphers, chosen by the `sqlite3` build-hook option in `pubspec.yaml`; `lib/data/local/db/database_file.dart`, `open_connection_native.dart`) with a random key from `SecretStore.databaseKey()`. A plain file from an older install is encrypted in place on first open; a file the key can't open is set aside as `app.sqlite.unreadable` and the app starts empty (and says so). Never delete the key; the web build stays unencrypted.
- Auth token and other secrets: `lib/data/local/secret_store.dart` (`flutter_secure_storage`), injected into `ApiClient` and attached to every request as `X-Import-Token` via a Dio interceptor. Non-secret settings (backend URL, budget syncId/name) live in `lib/data/local/settings_store.dart` (`shared_preferences`).
- API layer: `lib/data/api/importer_api.dart` and `categories_api.dart` are thin wrappers around `ApiClient`/Dio, mirroring the backend's `/parse`, `/import/confirm`, `/categories*` routes described above.
- `packages/statement_parser/`: pure Dart bank parsers and `importedId` (ported from the backend's, which are now removed) (no Flutter; `cd mobile_app/packages/statement_parser && dart test`). Reads both text shapes: pdf.js's (the old backend extractor's, which splits table rows and glues columns) and PDFium's (`pdfrx`, the app's, one row per line). Ids must match the backend's exactly or past imports duplicate; `fixtures/imported-ids.json` pins them. `test/real_statements_test.dart` checks real statements in `backend_app/Docs/tests/` (`<name>.pdfium.txt` against the backend's `<name> Extraction.json`) and skips when that folder is absent. The app's `test/pdf_text_extractor_test.dart` does the same from the PDFs with the real PDFium; `flutter test` doesn't hand the build hook's native library to host tests, so it points `Pdfrx.pdfiumModulePath` at `build/native_assets/<os>/` and skips until that exists (first `flutter test` or `flutter build linux`; the hook needs clang on Linux).
- Screens live under `lib/features/<feature>/screens/`, mirroring the backend's flow: `import` (inbox of statements) → `review` (edit parsed transactions, `review_screen_args.dart` carries the parse result across the route) → confirm import. `dashboard` reads `GET /dashboard`; `accounts` pages `GET /accounts/:id/transactions`; `budget` reads `GET /budget-month`; `quick_add` posts `POST /transactions` with one `clientId` per form, so a retried save never adds twice; `category_memory_screen.dart` manages the payee→category mappings.
- Design system: tokens (`Space`, `Radii`, `AppTokens`, `figures()`) in `lib/core/theme/app_theme.dart`, shared widgets in `lib/shared/widgets/`. Fonts (Geist, Geist Mono) are bundled in `assets/fonts/`, never fetched at runtime. Charts use `fl_chart`.
- `receive_sharing_intent` is pinned to the 1.8.x API for Android share-sheet PDF intake — see the doc comment above that dependency in `pubspec.yaml` before bumping its major version.
